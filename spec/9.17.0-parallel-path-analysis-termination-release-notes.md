# Release Notes — 9.17.0 Parallel Path Analysis Termination

`machine:paths` no longer segfaults on machines with re-entrant parallel states, and
`machine:scenario` no longer answers "No path" for targets that are genuinely reachable.
**Read the upgrade section before updating**: the same work makes path enumeration follow routes it
used to drop, so path counts rise sharply and every coverage percentage measured on such a machine
falls.

## Before you upgrade

The headline is not the crash — it is that **`assertAllPathsCovered()` will fail where it passed**,
and `machine:coverage --min` gates will drop below their thresholds. Nothing regressed: the earlier
figures were measuring less than they claimed. Upgrade on a branch, run
`php artisan machine:paths` on your machines, and re-baseline the thresholds against the new
numbers.

## Fixed

- **`machine:paths` exit 139 (SIGSEGV) on machines with re-entrant parallel states.** Region
  enumeration used a fresh enumerator with an empty visited set and its own path budget, and region
  states inherit parent-chain transitions — so a region walk escaped its region, walked the whole
  machine, and on reaching any parallel state spawned another empty-visited enumerator. Unbounded
  mutual recursion, C stack overflow. Three production machines that reported nothing now complete
  in 2–5 ms. The boundary is now structural (parent object identity), not an id prefix, and the
  visited set, path budget and analysed-parallel set are shared across region sub-enumerations.

- **`machine:scenario` reported "No path" for reachable targets inside a parallel region.**
  `ScenarioPathResolver::getNextStates()` followed only `@done`/`@fail`/`on` from a parallel state
  and never descended into region initial states, so every state inside a region was unreachable.
  This was a second, independent bug — the resolver never crashes, it exits 0 with the wrong answer.
  Region entry is labelled `@region` rather than `@entry`, because entering a parallel state
  activates every region at once: a single-region route is a projection of a concurrent
  configuration, not an exclusive descent.

- **Final states were treated as terminal by both analysers.** A route continuing out of a final
  state was invisible — yet `findTransitionDefinition` walks the parent chain with no special case
  for `FINAL`, so an ancestor's handler does fire from a final child; a compound `@done` whose guards
  all fail leaves the machine resting there; and a final state that delegates still has its
  `@done`/`@fail` routes. All three are now followed. **This is the change with the largest blast
  radius — see Breaking.**

- **Truncated enumerations were counted as coverage.** A path the enumerator cut short can never be
  matched by an observed run, so leaving it in the denominator made `assertAllPathsCovered()`
  unsatisfiable; it is now excluded from both the denominator and `uncoveredPaths()`.

- **Half-walked coverage paths leaked between tests.** `PathCoverageTracker` moves a path out of its
  buffer only on reaching a final state, so a test that stops at an intermediate state left its
  steps for the next test's completion to flush out as one signature — a route no machine ever took,
  recorded against the wrong test.

- **The `machine:*` commands raised where an exit code belonged.** `machine:paths`,
  `machine:coverage`, `machine:xstate`, `machine:scenario` and `machine:scenario-validate` now print
  a reason and exit `1` for a class that is not a `Machine`, one that never overrides `definition()`,
  one whose `definition()` returns `null`, and one whose `definition()` throws anything at all. The
  three commands that also accept a **file path** were worse: resolving one `require_once`s the file,
  and a path that is a directory, is unreadable, cannot be parsed, or throws while loading each
  raised. `php artisan machine:paths src/Analysis` was enough to hit it.

- **`machine:paths` now names child machines it could not analyse.** The unhandled-outcome check has
  to skip a child whose definition cannot be built, but skipping it silently made that child
  indistinguishable from one whose outcomes are all handled.

## Added

- **`PathCoverageTracker::discardActivePaths()`**, called automatically from
  `setUpTracksPathCoverage()` and `setUpInteractsWithMachines()`. Observed paths are untouched. It
  runs at set-up rather than teardown on purpose: trait teardowns fire LIFO under Testbench and FIFO
  under Laravel, so a teardown discard can land before another trait's teardown completes a path and
  silently swallow it.

- **Truncation is disclosed on the coverage surface.** `PathCoverageReport::enumerationTruncated()`
  and `skippedPathCount()`; `machine:coverage` prints a warning and adds `analysis_truncated` and
  `skipped_paths` to its JSON.

- **Observations the analysis cannot match are reported** as `unmatched_observed` in the JSON and a
  console warning. Disclosure, not a gate — see Known limitations.

- **`--max-iterations` on `machine:scenario` and `machine:scenario-validate`**, so a search that hits
  its ceiling is reported as *truncated at the search limit* — a different answer from "no path".

- **Numeric CLI options are validated.** `--max-paths`, `--max-depth`, `--max-iterations`, `--min`,
  `--path` and friends: a non-numeric or out-of-range value now fails the command instead of being
  coerced to `0`. That mattered most for `machine:scenario --path`, where zero is a valid index —
  `--path=abc` used to scaffold path 0 and report "Created:".

## Breaking

- **Path counts rise sharply, so coverage percentages fall.** On the three production machines this
  was validated against, the totals went **239 → 878**, **99 → 390** and **223 → 862**. Read those
  "before" figures precisely: they are **mid-release**, measured once the crash was fixed but before
  the final-state change. 9.16.0 produces no number for those three machines at all, because
  `machine:paths` segfaults on each of them.

  How much a given machine moves depends on which shapes it uses, and the range is wide: measured in
  isolation the final-state change alone ran from 1.0× (a machine with none of the three shapes) to
  12.5×, and a plain compound machine with no parallel state at all — a guarded compound `@done` plus
  a root-level handler — moved 2 → 8. **Do not read any single ratio as a rule**; measure your own
  machines before and after.

- **`assertAllPathsCovered()` and `assertPathCoverage()` now fail when the enumeration was
  truncated** by either ceiling, instead of reporting coverage over a partial analysis. Both take
  `maxPaths` and `maxDepth`, so a machine that legitimately needs more room can say so.

- **`--path` indices are not stable across this release.** The region descent also changes the answer
  for targets that *already* resolved: it adds routes passing through a region on the way to a target
  outside it, so `resolveAll()` returns more paths for an unchanged query — measured 1 → 3 on a test
  machine. `machine:scenario` now prints "Found N paths" and offers a `--path=N` chooser where it
  used to scaffold silently, so a script pinned to `--path=0` may scaffold a different route.

- **`machine:scenario` validates the scenario name.** It must be a PHP class name — a letter or
  underscore, then letters, digits or underscores. A name containing a path separator previously
  wrote the file **outside** the `Scenarios/` directory and still reported "Created:", and a name
  containing PHP syntax was interpolated into the generated class file verbatim.

- **`--max-paths` now bounds region paths and machine paths together.** It was applied per region
  before, so a parallel machine could enumerate far past the ceiling without noticing. A machine
  that previously fitted under the default 1000 may now report itself truncated — and since
  truncation fails the coverage assertions, that can newly fail a suite. Raise `--max-paths`.

- **Transitions between sibling orthogonal regions are rejected at definition time.** Regions are
  independent; use events (`raise()`, `sendTo`) for inter-region coordination.

## Expect to find dead scenarios on the first upgrade

Because `machine:scenario-validate` could not get far enough to load a scenario on a machine that
crashed, a scenario whose imports had rotted stayed silently broken. The first run after upgrading
finds them. One consumer's upgrade surfaced a scenario that had been dead since an unrelated
namespace move, reported as `include(...): Failed to open stream`.

This is the fix working, not the upgrade breaking something — but it will look like the latter, so
run `machine:scenario-validate` before concluding anything about your own change.

**Calibrate `--max-iterations` on large machines.** The default of 1000 is low for a real machine:
one consumer's machine reports "truncated at the search limit" on a query whose answer is already
complete, and needs `--max-iterations=50000` before the warning clears — with the same 8 paths at
every ceiling. The warning now names the ceiling it hit so you can tell which number to raise past.

## Known limitations

Recorded in §12 of the spec rather than fixed, so the next reader inherits them:

- The region boundary tests a transition's target, never its source, so a transition declared *on* a
  parallel state whose target is inside its own region is still followed by region enumeration.
  Diagnostic output only — region paths never enter the list coverage reads.
- Parallel-group reuse is order-dependent: a parallel reachable by both a short and a long route is
  analysed on whichever route reaches it first. The verdict is disclosed either way.
- A targetless self-transition (`on PING => ['actions' => …]`) is dropped with no path and no
  truncation flag. Pre-existing, not a regression of this release.
- An unmatched observation is reported but not asserted on: the tracker records a region leaf id
  where enumeration records the parallel container, so every parallel machine mismatches. Making it
  a gate needs the tracker to produce comparable signatures first.
